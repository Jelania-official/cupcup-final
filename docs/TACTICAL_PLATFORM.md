## 当前实现更新（2026-10-07）

以下旧版本成绩保留作历史记录，不应拿来评价当前 `bounded-2d-v3`。

v3 保留每台机器人的生产 `WorldModel` 历史，并按收到观测的时间更新/过期；不再
每帧新建地图。队友融合读取同一冻结快照，避免先决策的队员改变后决策队员的输入。
导航使用估计自机位置，无目标时也只在估计位置停止，不能暗中用真值修正定位。
网页以黄虚圆显示原始球观测、绿方框显示决策地图球位。近球执行抽象侧移/后退微调，
使用同一地图计算计划踢球朝向；近球平移预算为配置速度的 0.25，仍未实测校准。
realistic 的机器人位置置信度上限 0.25，不再以 0.5 当作可靠硬障碍；oracle 可用 1.0。
这批变化属于模型/接口修正，不能与 v2 比分直接比较来声称战术提升。

当前新增可解释的踢球门控计数：进入实际触球范围、面对球、朝向计划球路、停止且可
准备的累计机器人秒，准备中断次数和最长连续准备时间。它们是离线诊断，不进入决策；
两机累计可超过 PLAY 时长。网页也可切换踢球方向门槛和后卫 line/fixed 站位，导出的
JSON 包含实际参数，便于同种子对照。方向记忆只保留一条已选方向；角色/健康/观测
失效或球明显移动时撤销，不能为坚持旧计划忽略明显的新阻挡。

`abstract_opponent_revision=2` 修正脚本追球者的准备点：按球到球门的实际方向站到球后，
不再只沿横轴；宽侧来球不应因模型错误让对手无法准备踢球。物理模型仍是 v3；跨对手
修订的比分不能直接相减声称策略提升。shared 自对抗会同时改变双方策略，必须与固定
对手比较分开统计。最新同二进制留出对照和失败消融见
[测试记录](../src/cupcup/tests/TEST_REPORT.md)。

两种模式现在均用橙色箭头显示从地图球位到共享计划踢球目标的方向；旧回放的
`kick_x/kick_z` 字段仍兼容。过期地图球和非追球/解围行为不画球路。该箭头是计划，
不包含 ROS 图像执行器的局部射门修正，也不是球真实未来轨迹。

2026-10-08 近球绕路消融：将既有可靠障碍可见图用于近球目标，开发 288 场的总比分
仍为 12:0；固定对手完全信息子集阻挡时间减少，但平均推进从 -0.262 退化到 -0.386 m，

  左脚球速及滚动衰减用作名义参数，双方先取同能力，再独立调整对手。导出的沙盒 JSON
  附带所导入报告的 SHA256 与起点参数；实际修改后的参数仍以实验 `parameters` 为准。
  它不是完整校准，不能声称已测最大转速、碰撞、误差或接近微调时间。
- 踢球需要球距、身体朝向、停止与连续准备时间；统一抽签处理同帧多个有效踢球请求。
  圆盘碰撞拒绝双方平移，球路碰撞耗散速度。这是暂定运动模型，不是 Webots 步态。
- 角色保护按大禁区/中线，罚站触发按原活动裁判阈值。球过线进球/出界，100 模型秒
  不动重开；重开暂停 3 模型秒、罚站 31 PLAY 模型秒是实验约定。初始化为合法场内
  研究站位，未模拟完整边线入场；人工 INIT/READY/PLAY 与球不动的逐步判定尚不等价。
- 可用中场、己方半场、来球场景研究策略；边线/球门线场景用于机制检查，不能把
  已带初速度的球门线场景进球计成策略能力。
- 实时模式默认将估计和意图写入 `~/.local/state/cupcup/platform/*.jsonl`；网页支持导出
  最近 4500 帧、导入 JSON/JSONL 回放并拖动时间轴。沙盒实验也可导出完整 JSON。
  记录不含 Supervisor 真值；过期地图球和机器人候选不持续显示。

批量分层实验：

```bash
python3 src/cupcup/tests/evaluate_tactics.py \
  /home/j/.cache/cupcup/upstream-validation/install/cupcup/lib/cupcup/cupcup_sandbox \
  --seeds 8 --duration 180 \
  --output /home/j/.local/state/cupcup/tactics/baseline.json
```

它覆盖开发/留出种子、两种信息模式、4 种对手、3 种场景、慢/等速/快对手及双方换色。
记录比分、踢球、罚站、碰撞步数、重开与复现命令；另记录平均球位推进、对方半场时间、
己方禁区威胁时间、0.6 m 内无争抢近球机会、争抢/阻挡与球静止时间。它们使用模拟
真值作离线评分，不进入策略；近球机会不是控球率。换色结果是相关的旋转副本，不是两个
独立样本。全部物理与感知参数仍标为未完成受控校准；此报告不得解释成正式比赛胜率。

实验机制参考 [PettingZoo Parallel API](https://pettingzoo.farama.org/api/parallel/) 的
同时动作边界，以及 [RoboCup Soccer Simulator](https://rcsoccersim.readthedocs.io/en/latest/soccerserver.html)
将运动、踢球、衰减和重开分开建模的做法。未引入这些项目依赖或复制其参数/代码。

## 用途与边界

实时状态额外显示“本机球距”和 `ball_range_source`：地面投影、半径代理或来源未知。
这不是全局球图的来源/精度标签，也不表示曝光同步；旧回放缺失字段保持未知。
录制保存估计而非真值，离线真值对照仍由独立测量/比赛追踪工具完成。

2026-10-08 模型敏感性检查：`evaluate_tactics.py --setup 2.6` 可显式改变己方准备到
触球时间，同时保持对手的准备时间能力比。报告区分未测默认/测量来源/显式暂定值，
不会把 CLI 输入自动标成已校准。同种子、实测速率下两个 288 场对照中，有限信息
固定对手子集在 1 秒假设下为 6:0、2.6 秒下为 0:12；完全信息两组仍均 0:0。
这暴露了准备假设及完全信息僵持的问题，不是新的真实比赛成绩。默认 1 秒仍是
未验证实验值，研究本机策略必须显式设置并扫范围，不能依靠它作交付依据。

平台有两个模式，共用场地绘制和比赛状态格式：

1. **实时观察**只读订阅 ROS 2 比分/比赛状态和 `cupcup` 的 `Talk`。绘制策略实际发布的
   自机位姿、地图球位、战术动作及目标点；不会向机器人发控制命令，也不会从 Webots
   Supervisor 读取真值。没有敌方估计时留空，不用仿真真值补齐。
2. **独立沙盒**在本机快速运行 2v2 平面模型。双方球员遵守显式速度/转向上限；可选
   press、block、keeper、shared 四种脚本型对手，可固定随机种子和观测噪声，随后逐帧
   回放；批测对同一组种子分别运行红方/蓝方并汇总 cupcup 胜平负和场均进球，降低单侧
   开局偏差。策略直接调用生产头文件 `match_policy.hpp` 的统一状态/意图入口；
   机器人运动、视觉、踢球闭环和球物理目前是独立的**暂定模型**，并不是 Webots 的
   拟合副本，也不能据此宣称能击败真实队伍。

沙盒同时保留模拟真值球和带噪声的策略观测，界面以不同图形区分它们。策略输入只取
观测值；真值只用于可视化、物理裁判和离线评分。`--seed` 固定后，完整输出应可复现。
当前默认单轴观测噪声 σ=0.20 m，是参照一场 Webots 记录中约 0.25 m 的球地图误差中位数
所设的粗略起点，不是已拟合的传感器概率分布。
踢球速度默认 0.9 m/s，来自两个 120 秒 Webots A/B 局观测到的约 0.88–1.03 m/s 球速峰值；
球滚动衰减初值 0.9/s 与 trace 拟合约 0.68/s 接近。样本仍少、场景非受控，两者均可调且
仍属校准初值，不是球的完整碰撞/运动学模型。

## 启动

构建并 source 当前工作区后：

ros2 run cupcup cupcup_visualizer
```

默认监听 `http://127.0.0.1:8765`。实时观察要求 ROS 2 环境中有 `common` 消息类型和

```

服务默认只绑定本机地址；如显式改为其他监听地址，应只在可信网络使用。网页服务不具备

## 校准与迭代准则

不要为得到好看的分数而调参。首先用 `docs/TACTICAL_SIMULATION.md` 中的 Webots 记录，
分开测平移/转向上限、踢球初速度与方向散布、球滚动衰减，以及定位/球观测误差和延迟；
再将测量分布作为沙盒参数并保存来源、样本数与范围。每次策略比较都使用相同开局和多组
固定种子，覆盖红蓝方向、不同对手类型，并同时报告胜平负/净胜球、球权切换、有效射门、
边界违规和健康停机。保留未调参种子作留出集。

批测接口使重复场景更方便，但这些汇总仍来自未校准的模型，不是策略效果证据；脚本对手不是其他球队的行为模型。实时
观察以 cupcup 自身遥测为主；最多显示 4 个低可信机器人候选，并区分红、蓝、未知与
局部关联 ID。它们不是可靠的号码或跨机身份，位置未充分标定、暂不驱动地图对抗。
空白代表没有可信输入，不代表场上没有对手。
