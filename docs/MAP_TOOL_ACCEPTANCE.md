## 启动

构建并 source 工作区后，运行：

```bash
ros2 run cupcup cupcup_visualizer --no-ros
```

浏览器打开 `http://127.0.0.1:8765`。本机现有安装环境的完整命令：

```bash
source /opt/ros/humble/setup.bash
source /home/j/.cache/cupcup/upstream-validation/install/setup.bash
ros2 run cupcup cupcup_visualizer --no-ros
```

终端 Ctrl+C 停止服务。需要实际比赛只读观察时去掉 `--no-ros`，先启动比赛。
页面不会发布机器人运动命令；其暂停不暂停 Webots。

## 五分钟试用

1. 进入“独立策略沙盒”，先使用默认参数运行。实验一次性生成记录，随后播放、
   暂停、单步、拖时间轴、调倍速。修改参数需要重新运行，不是在旧轨迹中途改物理。
2. 展开“初始场景编辑”，选择一个对象，点击编辑地图放置；可设置四台机器人的
   朝向及球的初速度。确认“初始状态”为自定义，再运行。初帧应与输入对应。
   球速单位 m/s，坐标米；0°朝 +x，90°朝 −z。重叠机器人应拒绝运行。
3. 关闭“模拟真值”，回到开头：初始决策地图尚未建立，应显示未知，而不是
   复制真实位置。单步观察地图出现；选择 red_1 或点击可见机器人，查看其球图、
   末次更新来源、年龄、行动目标和队友障碍。观察者筛选不隐藏真值背景，
   真值需要单独关闭。图层只控制画布，不删除底层数据。
4. 导出实验，修改种子，再导入刚保存的文件。参数应恢复，轨迹回到开头；
   相同二进制、相同平台重跑应一致。无完整输入的历史记录只回放，不承诺重跑。
   仅末帧文件应明确提示没有连续过程。
5. 切回“比赛观察”，导入历史 JSONL；播放/拖动并筛选观察者。过期信息不画为
   新鲜位置，详情仍可保留历史值并标“过期”；未记录的字段显示未知。
   “导出观测回放”应导出正在查看的记录，不是后台另一段历史。

本机可用于步骤 5 的已有记录：
`/home/j/.local/state/cupcup/matches/20261009-155910-red-vs-cupcup/belief.jsonl`。
这是历史四机同代码测试记录，不是当前新策略成绩。

## 分析记录

“导出实验”保存完整沙盒结果、输入与测量来源；离线查看时“导出观测回放”保存
当前整段回放，实时查看时只导出内存中的最近最多 4500 帧。完整实时实录由服务
持续写入终端显示路径下的 JSONL 文件，长时间记录应使用该文件。
“导出当前分析帧”保存当前帧、观察者、图层选择以及实验上下文或回放文件名，
供双方讨论同一时刻。分析帧仍包含完整底层帧，不是按筛选裁剪后的图片；沙盒帧
显式带 `truth_available=true`，不得将它当作机器人的实际感知。

实时显示会给最后收到的数据继续计龄，包括请求失败/卡住时；超过原有阈值的
位置从图上隐藏，详情仍保留原值并标过期。分析帧保留原始服务帧，并在
`context.client_age_s` 记录浏览器收包后经过的时间：重建当前显示时，将它加到
各机器人 `message_age_s` 上。离线回放的该值为 0，不随观看时间改变。
它不补偿未知的传感器采集/网络传输延迟，不能证明原始感知准确或绝对新鲜。
从回放恢复实时时先清空旧画面，等新状态；请求超时会重试，不叠加未完成请求。

实时 Talk 的 `bx/bz` 是看见球时发布的球图坐标，不是原始视觉测量。
界面将其归到地图层，原始球观测坐标显示“未记录”。`mapped_ball_source`
只表示最后一次被接受的更新来源，不表示整条滤波历史都来自该来源。
候选位置和共享障碍不代表可靠身份识别；没有候选不代表场上没有对手。
